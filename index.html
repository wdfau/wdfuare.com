Case 01 · UX 分析 · 2026.11

Cursor 界面易用性改进

一名初级设计师想用 Cursor 做设计初稿，却在两处卡住：开始时选不对入口，修改时选不准对象。这篇拆解问题出在哪，以及可以怎么改。

01 — Background

背景与问题

想象你是一名初级设计师，想用 Cursor 看看团队现有的设计、找点灵感，再做一份初稿。任务可能是一套伴手礼、一张海报、一张流程图，或一个简单页面。

进入软件后，你不知道该选哪个入口。打开本地文件夹、输入需求后，AI 开始建立 Git 仓库、搭建环境。你不清楚自己为什么进了这条流程，也不知道它和这次设计任务有什么关系。

开始修改设计后，又遇到另一类困难：在这次使用的画布里，主要靠按住鼠标拖动、涂画来标记位置，很难逐层找到想改的对象。AI 有时还会改到不需要改的内容。

本案例聚焦两件事开始时，能不能选到符合预期的入口；修改时，能不能准确选中目标，并看清 AI 将修改的范围。
02 — User

用户

想用 AI 提升效率、熟悉设计软件、但不熟悉开发流程的初级设计师。他们有基本的视觉判断力，愿意用对话表达需求，也愿意在初稿上自己动手改。

材料说明：依据使用者反馈、当前操作截图与官方功能说明整理。没有开展多用户访谈、方案原型测试或上线效果验证。

03 — Problem 1

问题一：入口选择不清晰

用户想做的是：让 AI 理解现有设计，给出想法，再开始做初稿。他首先关心创作目标，而不是先决定代码仓库、开发环境或版本管理。

实际情况是：开始任务时，没有找到清楚对应设计用途的入口。之后出现了建立 Git 仓库、搭建环境等操作。这超出了用户的预期，用户也不认为这是自己主动选的。

需要判断的事这次体验中的困难
入口是否适合我看到了入口，但不清楚哪个对应当前的设计任务。
选择后会发生什么难以预判会直接进入设计创作，还是进入仓库相关流程。
文件将怎样管理不清楚这次任务需要 Git，还是普通文件夹就够。

用户在开始创作前，就要花精力猜入口的含义。进入非预期流程后，又要判断继续、返回还是重来。理解和纠正的成本都变高了。

问题归纳入口没有帮用户建立清楚的操作预期，用户难以主动选择适合当前任务的工作方式。

事实边界：官方入门允许直接打开本地文件夹 [1]；名为 Projects 的功能采用云端仓库流程 [2]。本案例不认定所有任务都必须用 Git，也没有确定本次具体由哪个入口或设置触发了仓库操作。

04 — Problem 2

问题二：画布选择不准确

用户想做的是：在已经生成的初稿里，只改一块内容。比如只调整一个流程节点的文字，保留其他节点和连线。

图片由使用者提供，只裁取相关区域。截图用于说明选择与标记方式；"AI 改了无关内容"来自使用者反馈，图片本身不展示修改前后的结果。

  1. 位置是模糊的。拖动、涂画表达的是大致位置，用户难以确认当前到底选中了哪个对象。
  2. 层级不好认。整张图、内部节点和文字之间的层级不容易分辨，定位局部内容要反复尝试。
  3. 改动会越界。选区和实际修改范围不一致时，用户要额外检查、恢复无关的改动。
问题归纳用户难以准确指定修改目标，也难以判断自己的选择会怎样约束 AI 的实际改动。

产品边界：Cursor 已有 Canvases [3]。官方说明，浏览器中的 Design Mode 支持点选、多选、框选和父子层级切换，Canvas 标签页的行为又有所不同 [4]。这里研究的是本次画布中的操作困难，不把它概括为整个产品缺少选择能力。

05 — Solution 1

改进一：把入口用途说明白

让用户在开始对话前就知道该选哪里，以及选了之后会进入什么工作方式。

让用途选择更容易发现

把用途选择放在新建任务时容易看到的位置，避免进了一条流程才发现不合适。角色可以帮助理解，但更要让用户说出这次要做什么：做海报、整理流程图、做页面初稿，还是开发功能。

用任务描述解释入口

需要呈现的信息建议表达的内容
适合什么任务用普通语言说明能在这里完成哪些事，帮用户对照自己的目的。
进入后先做什么说明是先看和改视觉初稿，还是先处理已有代码和开发环境。
是否涉及仓库说清是否用 Git、是否连接远程仓库；需要时解释理由。
当前选择是什么进入后保留清楚的用途提示，并提供好找的返回或切换入口。

让选择和后续行为一致

用户选了设计创作，后续操作就应围绕这次设计任务。如果确实需要切到代码开发或仓库操作，先说明变化和原因。这不等于删掉仓库能力，重点是让这些行为有清楚的说明，并符合用户的选择。

代价

直接解释任务和后续行为，比只加一个职业标签更能帮用户判断。代价是开始时可能多一次选择，所以应允许熟练用户跳过，或沿用上次的选择。

期望变化用户在输入需求前，能说清自己为什么选这个入口，以及接下来大致会发生什么。
06 — Solution 2

改进二：让修改目标明确可见

提供清楚的对象选择和范围反馈，减少 AI 对非目标内容的改动。

操作方式适合的情况需要看到的反馈
点选改一个节点、一段文字或一个元素。高亮对应对象，显示它的名称或内容摘要。
框选一次改多个对象。高亮实际包含的对象，而不是一个含糊的范围。
逐层选择整体里还有分组、节点或文字。能从整体进入分组和具体元素，看清当前层级。

先让已有的选择能力更好发现、更好用，再判断是否要补功能。涂画可以保留，作为说明位置、表达意图的辅助。

提交前，看得见选中了什么

在输入修改要求的位置，同时显示当前选中的对象和范围，比如"已选中：校验卡密节点"，并在画布上持续高亮。用户可以增减对象或取消选择，再提交。

实际改动和选择对应

把选中的对象和文字要求一起交给 AI，并在结果里标出实际改动。只加一个选中框不能保证 AI 只改局部，还需要系统识别对象、传递范围，并检查改动是否超出用户意图。

代价

层级太深、工具太多也会增加负担。所以常用的点选和框选要好找，层级信息按需展开。普通图片不一定有可编辑的图层，这是方案的边界。

期望变化用户改之前能确认目标，改之后能看出变化；无关改动更少，检查和恢复的负担更低。
07 — Validation

怎样判断改进是否有效

下面是后续可以检验的标准，不是已经取得的结果。

对应问题可以观察的行为
入口选择不清晰能否独立找到适合任务的入口；能否说清下一步会发生什么；是否误入流程再返回重选。
画布选择不准确能否选中指定对象；要重选几次；提交前是否理解修改范围；AI 的改动是否涉及非目标内容。

尚未确定：完整的首次进入路径、客户端版本和配置，仓库操作的具体触发原因；也没有 AI 误改的前后对比、方案原型或测试数据。所以本稿呈现的是使用反馈、问题分析和改进假设，不主张已经证明了改善效果。
